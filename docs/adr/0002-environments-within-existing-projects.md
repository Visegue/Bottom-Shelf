# Separate environments within the existing projects

Bottom Shelf uses one Vercel project with its built-in Development, Preview and Production environments, and one Neon project with separate database branches for production and non-production work. Separate projects are not required for the prototype; the environment boundary must instead be enforced through branch-specific credentials, scoped storage access and verification of actual database identity before privileged changes. This accepts more explicit credential and branch-lifecycle management in exchange for keeping provisioning and configuration within the existing projects.

Local development runs the application on the developer's computer against its own Neon development database; a local PostgreSQL installation is not required. Per-PR databases are preferred if they can be operated simply within the free allowances, with a shared preview database accepted as a deliberate fallback if that proves impractical or requires extra cost. The preview choice remains conditional until Auth configuration and branch lifecycle have been verified.

At the free preview-capacity limit, new previews wait or fail with a clear capacity message; closed PR resources are cleaned up automatically. Capacity exhaustion must not trigger a paid upgrade or silently replace isolated previews with a shared database. Limits and the chosen topology may be revisited explicitly after observing actual usage.

Development and previews share a stable non-production Auth service while application data and images remain isolated by environment; production has its own Auth service. This choice avoids configuring Google callbacks for every disposable preview, but must be verified with the actual Managed Auth integration before implementation is accepted. Project-wide Neon and Vercel management credentials must remain in trusted orchestration, isolated from execution of PR-controlled code; separate database hosts alone do not establish credential isolation when branching can copy role passwords.
