# Preserve manually entered non-production data and identity

Development and preview may contain manually entered non-production inventory instead of only generated fixtures, and ordinary startup, deployment or migration must not discard those data. An explicit development reset may discard application data and images while preserving the stable non-production Auth service, OAuth configuration and owner identity; populated inventory must belong to the actual verified owner's Auth identity rather than a guessed email or invented user ID. This trades automatic replacement of all test state for an explicit reset boundary and requires verification that reset cannot change Auth or production resources.

New previews start from a saved non-production reference dataset that can be deliberately supplemented with manually entered data, rather than automatically copying production data or ongoing development experiments. Preview edits remain isolated, are discarded when the PR closes and are never automatically written back to the reference dataset. Development reset can restore the same reference dataset, and a separate explicit command saves selected development data and images as updated reference data outside version control, tied to the verified owner identity.
