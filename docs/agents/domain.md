# Domain docs

## Layout

This repository uses one domain context:

- `GLOSSARY.md` at the repository root for agreed domain terms.
- `docs/adr/` for architecture decision records.

Create terms and ADRs as they are resolved through domain modeling.

## Before exploring

Read `GLOSSARY.md` and ADRs relevant to the work. If they do not exist, continue without creating placeholders.

## Vocabulary and decisions

Use the glossary's terms when discussing domain concepts in code, issues, and documentation.

When a needed term is missing, resolve the gap through domain modeling.

If a proposal conflicts with an existing ADR, identify the conflict explicitly and explain why the decision should be revisited.
